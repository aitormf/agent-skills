# Decisions

Why the system is the way it is: architecture choices, business rules and approaches that were tried and discarded. The code and the tests say **what** it does; this directory says **why**.

**Before changing code,** find the rows whose *Affects* covers the paths you will touch and read those decisions. Do not read them all.

**To contradict an accepted decision,** do not change it silently: write a new one that supersedes it. Accepted decisions are not edited.

**To add one,** use the `record-decision` skill, or copy the template with the next free number and add its row here. Check with `check_decisions.py docs/decisions`.
